1. Executive summary

0 / ~1,500strategy variants (trials) passed their pre-registered criteria (NSE + crypto)
0strategies that passed (one lead, SOL 1h shorts, is suggested for a paper test only)
813automated tests on the bot code (CI green, ~98% coverage)
2 marketsNSE India (equities, daily futures) and crypto (SOL, BTC)
Bottom line. The software (data layer, indicators, strategies, risk, backtester, ML filter) is built and audited. Every strategy tested, on both NSE and SOL, was not profitable after realistic costs. Gross edge was close to zero; costs consumed the rest. Nothing is ready for live money.
  • Built: milestones M0–M4.1 plus ML1 (LightGBM filter) and a results dashboard. M5 (live feed and Telegram alerts), M6 (AI review) and M7 (deployment) are not started.
  • NSE intraday (1m–60m): net loss in every tested form; gross ≈ 0 to +0.03R per trade, costs ≈ 0.9R per trade at tight stops.
  • NSE swing (daily/4h): 0 of 300 variants passed. Best one (+0.32R in 2024) is probably market drift; deflated Sharpe 0.04 (needs 0.5).
  • ML filter (LightGBM): high AUC (0.84–0.89) only reflects stop/target geometry; no directional edge. OOS loss reduced only by trading less.
  • Crypto SOL: 8 studies, 0 passed. The only mildly consistent pattern is 1h shorts (+0.11 to +0.30R in 2024), but it fails the significance bar and is contaminated by repeated looking.
  • Recommendation on record: stop historical parameter-mining; if continuing, run a pre-registered paper test on fresh forward data.
Unit note. R = profit in multiples of the initial risk (distance entry→stop). −1R = a full stop-out. "Net" = after all costs; "gross" = before costs.

5. ML signal filter (ML1) — LightGBM vs logistic regression

  • Idea: train a model on every candidate setup to decide which to take.
  • Design: next-bar-open entry, all Indian costs, purged and embargoed walk-forward CV; model selection on 2022–24 only; frozen config committed before the single OOS run (2025-01 → 2026-10-16, run once at 14:43 UTC, 19 Oct).
  • Sizing: ₹10,000 per signal, with a size sweep to ₹5 lakh.
OOS variant (₹10k per trade)TradesNet P&L (min(₹20,0.03%))Net P&L (flat ₹20)
Unfiltered4,666−₹1,05,576−₹2.95 lakh
Logistic regression4,347−₹99,619−₹2.76 lakh
LightGBM3,383−₹77,031−₹2.15 lakh
Why the high AUC (0.84–0.89) is misleading. The leakage audit passed (shuffled-label AUC ≈ 0.5; no future features; purge correct). The AUC comes from barrier geometry: target distance vs volatility vs time left. An untrained formula scores AUC 0.825. Gross R is ≈ 0 in every prediction decile, so the model has no directional edge; it only filters out high-cost setups and loses less by trading less. The model was never wired to alerts.

9. Method and safeguards

SafeguardHow it was applied
Pre-registrationRules, grid and pass criteria committed to git before any trial; commit order verified for every study.
Data splitsNSE: in-sample 2022–24, OOS 2025-01 → 2026-10. Crypto: selection 2021/22–23, validation 2024, OOS 2025+. Code guards block later data in in-sample runs.
OOS disciplineOOS marker file written once; no re-tuning afterwards.
Multiple-testing controlEvery trial counted; deflated Sharpe ratio required > 0.5; neighbouring parameters must also be positive (plateau).
Typical pass criteria≥60 trades; net R > 0 and still > 0 at costs ×1.5; beats random by ≥0.1R; positive in both halves of 2024; drawdown reported.
Execution realismFill at next bar open plus slippage; stop-first if stop and target hit in the same bar; gap-through-stop at the open; full costs.
Leakage and look-ahead203 truncation checks; indicator causality tests; label-shuffle test; purged and embargoed CV.
Result retentionAll runs archived with config, commit SHA, log and trades in /workspace/data/results_archive/ with an INDEX.csv. Nothing deleted.
Code qualityMutation checks on core logic; CI gate (lint, types, tests, coverage); each merge reviewed critically.

10. Problems, mistakes and deviations (disclosed)

  • Worker agents: several background workers ended early because a text-only reply ends a run, or ran out of output length. Fixed by putting specs in files and requiring a tool call in every message. Finished workers sometimes kept running ("zombie" workers) and collided with their replacements; I now wait and verify first.
  • My errors: ran git checkout main inside a worker's tree (restored, no loss); a chained gh pr merge plus branch delete closed PR #4 (recovered; code is on main); a pytest pipe hid a failure in a gate chain (rule recorded).
  • Stale numbers: the first M4a results used signal-bar-close fills and are superseded by the post-M4.1 re-run.
  • Holdout exposure: an exploratory SMA per-year split printed 2025–26 data; disclosed (both sides were negative in 2025). 2024 crypto validation is also contaminated by repeated looking.
  • Unreviewed items: a post-OOS lint commit in CRYPTO1 touched 338 lines (stated behaviour-preserving, not independently verified). I mis-stated one break-even figure (58.5% vs the correct 54.3%) and one R value earlier; both corrected.
  • Licensing: Upstox terms of use for bulk historical data not reviewed; use is personal research only.
